# 数据模型与解析规范

## 一、统一事件模型

建议字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | String | 应用内部稳定 ID |
| `source` | Enum | `UNIVERSITY` 或 `PART_TIME` |
| `sourceRecordId` | String? | 原始课节 ID；兼职课优先使用 |
| `title` | String | 课程名或兼职课节标题 |
| `description` | String? | 教师、学生、课节状态等 |
| `location` | String? | 教室或上课地点 |
| `startTime` | LocalDateTime | 开始时间 |
| `endTime` | LocalDateTime | 结束时间 |
| `status` | Enum | 待上课、已完成、取消等 |
| `reminderMinutes` | Int? | 提前提醒分钟数 |
| `sourceFileHash` | String | 来源文件指纹 |
| `eventFingerprint` | String | 内容去重指纹 |
| `calendarEventId` | Long? | Android 日历事件 ID |
| `rawText` | String? | 原单元格文本，便于审计 |

## 二、事件指纹

### 校内课程

稳定键建议：

`source + 日期 + 大节编号 + 规范化课程名 + 规范化教室`

教师变化通常视为事件修改，不应导致创建重复事件。

### 兼职课程

优先使用表格中的课节 ID。没有课节 ID 时再退化为：

`source + 开始时间 + 结束时间 + 学员 + 课节名称`

## 三、校内课表解析器

### 已观察结构

- 老式二进制 `.xls`。
- 主工作表为按周展开的网格。
- 每个区块包含周次、日期、星期和第一至第五大节。
- 有课单元格包含多行文本：课程名、教师、周次和节次、教室。
- 工作簿可能存在轻微 OLE 流长度异常，因此解析失败时需要备用读取策略。

### 解析步骤

1. 找到包含“周次/日期”的区块起点。
2. 读取本区块各列的实际日期。
3. 将行标题映射到第一至第五大节。
4. 对非空课程单元格按换行清洗。
5. 识别课程名、课程类型、教师、形如 `1-0102` 的周次节次和教室。
6. 以区块日期为准生成事件日期；周次字段用于交叉校验。
7. 根据春季/夏季作息映射开始和结束时间。
8. 保存原始单元格文本，异常时供用户校对。

### 容错要求

- 忽略多余空行和 `\r`。
- 不假设教师只有一人。
- 不假设教室名称长度或校区格式固定。
- 同一天同一大节可能出现多个课程描述，应进入冲突校验。
- 日期无法解析时不猜测年份，标记为异常。

## 四、兼职课表解析器

### 已观察结构

- 文件扩展名为 `.xls`，实际内容是 OOXML 工作簿。
- 主要数据位于“学员排课”工作表。
- 包含主讲、学员、课节名称、课节 ID、状态、精确上课时间等字段。

### 默认映射

| 来源字段 | 目标字段 |
|---|---|
| 课节 ID | `sourceRecordId` |
| 课节名称 | `title` |
| 学员姓名 | `description` |
| 上课时间 | `startTime`、`endTime` |
| 课节状态 | `status` |
| 课节类型 | 描述或标签 |

### 状态规则

- `待上课`：默认导入并提醒。
- `已结课`：默认不写入未来日历，可作为历史记录保存。
- 未知状态：不猜测，进入预览并要求用户确认。

### 隐私规则

- 默认不上传文件、学员姓名、学员 ID 或班级 ID。
- UI 中无需展示内部学员 ID、班级 ID 和教师 ID。
- 日志不得输出完整个人标识。
- 导出诊断报告时应自动脱敏。
