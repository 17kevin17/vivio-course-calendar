# 测试与验收门槛

## 一、P0 单元测试

### 作息数据库

- [ ] 同一季节可插入第1–5大节。
- [ ] 更新一个大节不覆盖其他大节。
- [ ] 春季和夏季配置相互独立。
- [ ] 非法 periodNumber 和重叠时间被拒绝。

### 课节 ID

- [ ] 样表中每个18位课节 ID 与工作簿原始字符串完全一致。
- [ ] 不出现科学计数法、尾数变化或负数溢出。
- [ ] 前导零 ID 如存在时不被删除。

### 身份和差异

- [ ] 同 identityKey、同 contentHash → UNCHANGED。
- [ ] 兼职课时间变化但课节 ID 相同 → MODIFIED。
- [ ] 校内教师变化 → MODIFIED。
- [ ] 校内教室变化 → MODIFIED。
- [ ] 新逻辑事件 → NEW。
- [ ] 未出现旧事件 → MISSING，不删除。
- [ ] 多候选匹配 → AMBIGUOUS，不自动更新。

## 二、数据库与导入测试

- [ ] Room 复合主键和索引符合设计。
- [ ] 一个 identityKey 只有一个 managed_event。
- [ ] 每个批次的每个 identityKey 只有一条 action。
- [ ] 连续导入相同文件三次，系统事件数量不增加。
- [ ] PARTIAL 批次可恢复或撤销。
- [ ] Calendar 成功、Room 写入前中断可以恢复。
- [ ] Room 记录成功、Calendar 操作失败不会伪装成 APPLIED。

## 三、撤销测试

- [ ] 撤销 CREATE 删除新事件。
- [ ] 撤销 UPDATE 恢复原标题、教室和时间。
- [ ] 撤销 DELETE 重建原事件。
- [ ] 撤销 NOOP 不修改事件。
- [ ] 撤销中途终止后可以继续。
- [ ] 撤销一个批次不影响其他批次的逻辑事件。
- [ ] 重复点击撤销是幂等的。

## 四、样表回归

- [ ] 校内课表识别出136个课程单元格。
- [ ] 兼职表识别出14条记录。
- [ ] 兼职状态统计为11条待上课、3条已结课。
- [ ] 校内日期、标题、教师、教室抽样核对。
- [ ] 夏季课程生成正确的100分钟事件。
- [ ] 春季下午时间未配置时产生 blocker。

真实样表不得直接提交公开仓库。测试夹具应使用脱敏后的最小工作簿。

## 五、vivo 真机测试

按顺序执行并保存结果：

1. 全新安装。
2. 导入校内课表。
3. 导入兼职课表。
4. 在 vivo 日历中核对随机10条事件。
5. 再次导入相同文件，确认数量不变。
6. 使用修改过教室和时间的脱敏文件导入，确认更新原事件。
7. 撤销修改批次，确认恢复原内容。
8. 撤销首次兼职导入，确认只删除对应事件。
9. 拒绝日历权限并检查预览仍可使用。
10. 清后台、重启手机，检查事件和提醒。

## 七、MVP 完整性验收门槛

以下条件必须同时满足：

- 所有 P0 自动化测试通过。
- 连续三次导入不重复。
- UPDATE 与撤销 UPDATE 均正确。
- 应用中断后无不可追踪日历事件。
- vivo 真机完成完整冒烟流程。
- 已知失败以结构化状态展示，不静默丢数据。
