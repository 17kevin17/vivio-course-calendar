# 课程日历 App：完整性修复冲刺交接包

## 本阶段目标

把当前“解析可用原型”推进到“可以安全进行 vivo 真机日历测试”的状态。

本阶段只解决完整性问题：

1. 作息配置可以正确保存五个大节。
2. 同一课程可以跨多次导入保持稳定身份。
3. 新增、修改、取消、缺失能够正确区分。
4. 撤销能够恢复更新前状态，而不是误删事件。
5. CalendarProvider 与 Room 之间发生中断后可以恢复。
6. 18 位兼职课节 ID 不发生精度损失。
7. 自动化测试能证明重复导入、更新和撤销正确。

## 明确不做

- 不新增账号、云同步或服务端。
- 不实现原子岛。
- 不实现 ICS、桌面组件、课程分享等 P1 功能。
- 暂不做完整隐私治理和隐私设置页面。
- 不大改现有 UI，除非完整性流程需要状态提示。

## 最低隐私底线

即使隐私治理暂缓，仍保持三条不会拖慢开发的约束：

- 不新增网络权限或上传逻辑。
- 日志不得输出完整学生 ID、班级 ID、课节 ID 和原始工作簿内容。
- 含真实个人信息的样表不得提交到公开 Git 仓库。
