# 事件身份与差异修复

## 一、校内 identityKey 碰撞

当前身份：

```text
UNIVERSITY + 学年 + 课程名 + 周次 + 节次
```

同一课程在同一周、同一节次但不同日期出现时会碰撞。真实样表中共有18组额外事件因此被 `distinctBy(identityKey)` 丢弃。

## 二、身份设计

### 事件发生实例 key

用于保证正常课次唯一：

```text
UNIVERSITY
+ 学期标识
+ 规范化课程名
+ 周次
+ 星期或实际日期
+ 节次码
```

推荐优先包含实际日期：

```kotlin
fun universityOccurrenceKey(
    semester: String?,
    courseName: String,
    weekNo: Int?,
    date: LocalDate,
    sectionCode: String?
): String
```

### 调课候选 key

日期变化不应通过压缩 occurrence key 来解决。单独生成候选匹配字段：

```text
学期 + 课程名 + 周次
```

只有唯一候选且满足明确规则时，才能建议“可能调课”；否则由用户确认。首版允许调课表现为 NEW + MISSING，只要不误删、不丢事件。

## 三、禁止静默去重

删除或替换：

```kotlin
distinctBy { it.identityKey }
```

建议流程：

1. 解析器输出所有事件。
2. 按 identityKey 分组。
3. 发现重复 key 时标记解析错误或 AMBIGUOUS。
4. 不得静默保留第一条、丢弃后续记录。

## 四、取消状态

DiffEngine 应先处理业务状态，再比较哈希：

```kotlin
when {
    event.blocker != null -> INVALID
    event.status == CANCELLED && existing != null -> CANCELLED
    event.status == CANCELLED && existing == null -> IGNORED_CANCELLED
    existing == null -> NEW
    existing.contentHash == event.contentHash -> UNCHANGED
    else -> MODIFIED
}
```

如不新增 `IGNORED_CANCELLED`，可将其作为 excluded NOOP，但必须在预览中说明。

## 五、导入范围

新增：

```kotlin
data class ImportScope(
    val semester: String?,
    val dateFrom: LocalDate?,
    val dateTo: LocalDate?
)
```

规则：

- 校内课表按学期和日期范围计算 MISSING。
- 兼职明细按本文件最早/最晚课节日期计算 MISSING。
- 文件若明确为全量导出，可标记 `isCompleteSnapshot=true`。
- 无法证明全量时，只报告潜在缺失，不改变 managed status。

## 六、提醒进入最终事件

在用户确认提醒设置后：

1. 把 reminderMinutes 应用到最终 UnifiedEvent。
2. 重新计算 contentHash。
3. 再生成 DiffPlan 或至少重新判定 MODIFIED。
4. 用最终事件生成 afterSnapshot。
5. managed_event 保存最终 contentHash。
